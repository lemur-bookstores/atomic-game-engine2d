## v0.6.0 - Logs & Errors Manager

## Resumen

Este documento define un sistema agnóstico de logs y manejo de errores para el motor `atomic-game-engine2d`. El objetivo es proporcionar una estructura común (EngineError), un servicio central (`ErrorHandlerService`) que normalice errores, los publique en el bus de eventos del motor y permita registrar distintos `ErrorHandler` que almacenen o reenvíen los logs al destino elegido (consola, memoria, localStorage, servidor remoto, descarga .json, etc.).

## Contrato mínimo (inputs / outputs)

- Input: cualquier `Error` o excepción capturada dentro del engine o por el desarrollador.
- Output: uno o varios registros almacenados o enviados, y eventos emitidos por el `EventSystem` para que el resto del motor/app pueda reaccionar.
- Forma de los datos: objeto serializable con campos estandarizados (name, message, code, details, sourceModule, isCritical, timestamp, stack).

## Puntos clave y edge-cases

- Errores con referencias circulares en `details` deben serializarse de forma segura.
- En ambiente navegador no se puede escribir directo a disco; proveer alternativas (localStorage, IndexedDB, descarga blob o envío HTTP a un backend).
- Handlers pueden fallar: `ErrorHandlerService` debe intentar handlers en secuencia y registrar fallos internamente sin bloquear el flujo primario.
- Errores críticos: emitir evento específico (`engine.critical_error`) y permitir que integraciones (telemetría, alertas) actúen.

### UI / In-App Error Display Handler

Descripción
-----------
Una alternativa al almacenamiento es renderizar los errores directamente en la UI de la aplicación web. Esto evita persistir logs y reduce uso de I/O, siendo útil en entornos donde se prefiera mostrar errores al desarrollador o al usuario (modo debug) sin almacenarlos.

Comportamiento esperado
-----------------------
- No persiste los logs por defecto (opcionalmente mantiene una memoria limitada en runtime).
- Debe ofrecer throttling y un límite de entradas para evitar saturación.
- Debe sanitizar cualquier dato mostrado para prevenir XSS cuando los detalles contienen HTML o texto no confiable.
- Debe exponer hooks/eventos para integrarse con frameworks (React/Vue) o con un panel DOM simple.

Ejemplo básico (DOM puro)

```ts
class UIErrorHandler implements ErrorHandler {
  constructor(
    private container: HTMLElement,
    private maxEntries = 50,
    private sanitize = true,
  ) {}

  canHandle(_error: EngineError) { return true; }

  async handleError(error: EngineError) {
    // Opcional: throttling / debounce
    const entry = document.createElement('div');
    entry.className = 'engine-error-entry';

    const message = this.sanitize ? escapeHtml(error.message) : error.message;
    entry.innerHTML = `
      <div class="engine-error-time">${error.timestamp.toISOString()}</div>
      <div class="engine-error-msg">${message}</div>
      <pre class="engine-error-stack">${this.sanitize ? escapeHtml(error.stack || '') : error.stack || ''}</pre>
    `;

    this.container.prepend(entry);

    // Mantener límite
    while (this.container.children.length > this.maxEntries) {
      this.container.removeChild(this.container.lastChild!);
    }
  }
}

function escapeHtml(unsafe: string) {
  return unsafe
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#039;');
}
````

Ejemplo (React hook) — recomendado para SPA

```ts
// useEngineErrors.ts
import { useEffect, useState } from "react";

export function useEngineErrors(eventSystem: EventSystem) {
  const [errors, setErrors] = useState<EngineError[]>([]);

  useEffect(() => {
    const listener = (ev: any) => {
      const err: EngineError = ev.payload?.error;
      setErrors((prev) => [err, ...prev].slice(0, 100)); // límite
    };

    eventSystem.on("engine.error", listener);
    return () => {
      eventSystem.off && eventSystem.off("engine.error", listener);
    };
  }, [eventSystem]);

  return errors;
}
```

## Integración y buenas prácticas

- Registrar el handler en `ErrorHandlerService` en lugar de persistir: `errorService.registerHandler(new UIErrorHandler(container, 50, true))`.
- Preferir sanitización por defecto y filtrar campos que contengan datos de usuario.
- Para SPAs, usar el `EventSystem` del engine para poblar un estado local (hook) y renderizar un componente accesible (role="status" o role="alert" según el caso).
- Añadir una opción de `config` en `Engine` para `enableInAppErrorPanel` o `errorPanelElement`.

## Consideraciones de rendimiento y UX

- Throttling: no mostrar más de N mensajes por segundo en pantalla.
- Límite de memoria: mantener sólo las últimas N entradas en memoria.
- No bloquear el hilo principal: renderizar entradas de forma asíncrona (requestAnimationFrame o microtask) si llegan muchas.
- Ofrecer opción para descargar un `.json` con las entradas actuales si se requiere análisis posterior.

## Seguridad

- Sanitizar/escape obligatorio cuando se muestre `details` o `stack` en la UI.
- Evitar inyectar HTML desde valores de `details` sin procesar.

## Integración recomendada con `Engine` (pasos concretos)

1. Crear archivos: `src/core/EngineError.ts`, `src/core/ErrorHandlerService.ts`, `src/core/Logger.ts` (opcional).
2. Inicializar en `Engine` (constructor o `initialize`):
   - Instanciar `Logger.init(config.debug)`.
   - Crear `const errorService = new ErrorHandlerService(this.eventSystem);`
   - Registrar handlers por defecto: `ConsoleErrorHandler`, y quizá `LocalStorageErrorHandler` si `config.enableLocalLogs`.
   - Guardar referencia en `engine` para uso por otras piezas.
3. Reemplazar llamadas directas a `console.error/warn/log` dentro del engine por `Logger` y cuando corresponda, envolver errores con `KernelError` y pasar por `errorService.handleError(err)`.

Ejemplo de uso dentro del engine:

```ts
try {
  // operación que puede fallar
} catch (err) {
  const k =
    err instanceof EngineError
      ? err
      : new EngineError(
          err.message,
          "UNKNOWN",
          undefined,
          "Engine",
          false,
          err
        );
  await this.errorHandlerService.handleError(k);
}
````
